# Evidence: where the facts come from and how far to trust them

## How the library was researched

AI research agents did all of the research. The 97 researched profiles come from agent runs that followed [`research/BRIEF.md`](research/BRIEF.md), dated 28 Oct 2026: each run took one category of about ten apps and wrote one file in `data/research/profiles/`. The six in-depth guides carried over from v2 are longer agent write-ups that keep official and reported timelines apart, and the four upgraded in v3 restructure existing profiles without adding facts. The brief sets these rules:

- **Web only.** WebSearch and WebFetch; official developer docs first, then the provider's help center or changelog, and only then community sources (Stack Overflow, GitHub issues, integration-vendor blogs) for real-world timelines and pitfalls.
- **No sign-ins.** No browser automation, no accounts, no logging in to consoles. A page that can't be fetched is not worked around; it goes in the guide's "uncertain" list.
- **Small budget.** Roughly 5–9 tool calls per app, stopping once the auth model, where to register, the approval gate, roles and testing are confirmed.
- **Say how sure you are.** State only what sources support, mark inferences "likely", lower the confidence, and list 2–6 source URLs.

The result: 103 guides (10 in-depth, 93 researched profiles) citing 367 source links (365 distinct URLs). Confidence is 29 High, 56 Medium and 18 Low. Console menu paths come from documentation, not from a signed-in console, so labels can differ from what you see.

### What the spot check changed

- **The offline generator (rows 4–7).** It used to fall back to self-serve OAuth whenever a category had no clear pattern, and it put names with no keyword into "Productivity & PM" without saying so. In v3.3.0 a default category is no evidence, a missing pattern means planning for a provider review, a name that matches nothing is labelled "not recognized", and provider approval reads **Unconfirmed** unless a vendor family (a researched app on the same developer platform) backs it. Unit tests cover Zoom, Spotify, Dropbox, "asdkjhqwe" and Confluence (a vendor family, which stays confirmed), and a browser test checks the label on a generated guide.
- **Close (row 8) is corrected.** A hand-reviewed path override in `data/research/overrides.json` moves it from self-serve to provider review, and its verdict, production gate and steps now follow Close's docs. The two pages in row 8 replace a link the original run cited but never read (its notes say Close's docs weren't fetched). Two headline numbers moved: 36 apps (was 35) need provider approval, and 28 (was 29) are self-serve. The medians didn't change, because Close publishes no review timeline.

## What's still unverified

- **Low-confidence guides.** 18 guides are Low confidence: treat them as hypotheses. Of the three checked here, one was wrong (Close, now corrected), one held up on a secondary source (QuickBooks) and one couldn't be fetched (Gumroad).
- **Pages that need JavaScript or a sign-in.** The rules forbid browser automation and accounts, so JavaScript-only docs (Intuit, Gumroad and others noted in each guide's "uncertain" list) and every signed-in console screen are unchecked.
- **Reported timelines.** The "reported" column of the in-depth guides comes from community sources, sometimes a single account (for example "one AI agent was approved in about 2 weeks" for Slack). Only 3 of the 18 partner-gated apps have any timeline at all.
- **Generated guides.** By design these are drafts: Low or Medium confidence, approval Unconfirmed without a vendor family, and a verify list. Pattern-based estimates can point the wrong way (row 6).
- **The live research agent.** It has never run against the real Anthropic API for this submission; its tests use a mocked API. Without an API key, live generation runs the offline engine.
- **Freshness.** The library reflects 28 Oct 2026. Provider rules change; Slack's install minimum, for one, changed in July 2026.
